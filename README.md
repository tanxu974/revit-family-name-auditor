# FamilyNameAuditor · Revit 族命名审计与规范化工具

> 把企业族命名规范变成可执行规则，一键审计 Revit 模型并批量规范化族名，过程可追溯、可交给甲方证明。

> 一个从建筑行业真实痛点出发的 BIM 自动化作品：规则与代码分离、只改能可靠推断的族、改名后自动复检、全程 CSV 可追溯。

## 痛点

设计院模型里，同一类风管的族名可能是 `风管1`、`新建族 (2)`、`Family37`。命名混乱导致：材料统计出错、交付规范落不了地、二次开发无从下手。人工逐个核对耗时且易漏——一个几百个族的项目，核对一遍要大半天。

这个工具把命名规范写成一份 JSON 配置，自动扫描、逐条列出违规原因、能推断的一键规范化，并导出审计报告。

## 效果

一键扫描 → 列出违规及原因 → 批量规范化（不可推断的保守跳过） → 导出审计报告 → 复检违规归零。

**实测结果（15 个测试族）**：

| 指标      | 结果  |
| ------- | --- |
| 扫描族数    | 15  |
| 初检违规    | 11  |
| 可安全自动改名 | 1   |
| 复检通过    | 1   |
| 保守标记人工  | 10  |

> 11 个违规只有 1 个敢自动改——**宁可多标人工，也不冒险改错**，这是工程工具该有的安全底线。

审计输出示例（命令行）：

```
[自动改名(复检通过)] 机电-风管-镀锌钢板-矩形-副本-400x300
     建议名: 机电-风管-镀锌钢板-矩形-400x300
[标记人工(不可自动推断)] 弱电-水管-PVC-圆形-DN50
```

审计报告 `audit_report.csv` / `rename_preview.csv`（Excel 可直接打开，UTF-8 BOM 编码无乱码）：

| 原名                       | 是否合规 | 违规原因                | 建议名                   | 处理方式       |
| ------------------------ | ---- | ------------------- | --------------------- | ---------- |
| 机电_风管_镀锌钢板_矩形_400x300    | 是    | —                   | —                     | 无需改动       |
| 机电-风管-镀锌钢板-矩形-副本-400x300 | 否    | 含非法词:"副本"           | 机电-风管-镀锌钢板-矩形-400x300 | 自动改名(复检通过) |
| 机电-风管-镀锌钢板               | 否    | 字段不足:3段(需4); 缺字段:规格 | 机电-风管-镀锌钢板            | 标记人工       |

## 功能特性

- ✅ 按可配置规则校验族名（字段数、枚举值、正则格式、非法词、全角符号）
- ✅ 违规项逐条给出**具体原因**与**建议名**，不是简单标红
- ✅ 审计前先做无损规范化（全角转半角、统一分隔符），避免误报
- ✅ 一键批量规范化，**无法可靠推断的保守跳过**并标记人工处理
- ✅ **复检闸门**：改名后用新名字再校验一次，改错的一律转人工
- ✅ 所有改名包在单个 Revit 事务里，失败整体回滚
- ✅ 导出 CSV 审计报告与改名对照表（改名前/后状态可追溯）
- ✅ 规则与代码分离，更换企业规范只需改 `rules/default_rules.json`，不动代码

## 安装与使用

### 方式 A：规则校验逻辑（无需 Revit，先看效果）

适合快速验证工具逻辑，不依赖任何 Autodesk 软件。

1. 下载 Python 3.x（或任意 Python 3 环境）
2. 命令行运行：

   ```
   python engine/audit_core.py rules/default_rules.json testdata/family_names.txt audit_report.csv
   python engine/apply_rename.py rules/default_rules.json testdata/family_names.txt rename_preview.csv
   ```
3. 用 Excel 打开生成的 CSV 查看结果

### 方式 B：Revit 里真改模型（完整功能）

**环境**：Revit 2024（自带 Dynamo 2.x / .NET Framework 4.8）

1. 打开 Revit → 管理 → Dynamo → 新建图 → 放一个 `Python Script` 节点
2. 把 `dynamo/rename_in_revit.py` 全文贴进节点
3. 设置三个输入：
   - `IN[0]` = 类别名，如 `Ducts`（对应 `OST_Ducts`）
   - `IN[1]` = 规则路径，如 `D:/FamilyNameAuditor/rules/default_rules.json`
   - `IN[2]` = `False`（**先只审计不改名**）
4. 先看 `Watch` 输出的对照表，确认违规原因和建议名都对
5. 确认无误后把 `IN[2]` 改成 `True`，才真正执行批量改名
6. 查看 `D:/FamilyNameAuditor/rename_report.csv` 获取改名对照报告

> ⚠️ 请先在 `sample_model/` 的测试模型上试用，勿直接对生产模型操作。第一次永远用 `False` 只审计。

## 规则配置

规则写在 `rules/default_rules.json`，**无需改代码**。示例分段规则：

| 段位  | 字段    | 类型     | 示例                                   |
| --- | ----- | ------ | ------------------------------------ |
| 1   | 专业    | 枚举     | 机电 / 给排水 / 暖通                        |
| 2   | 类别    | 枚举     | 风管 / 水管 / 桥架                         |
| 3   | 材质/形式 | 枚举     | 镀锌钢板 / 矩形                            |
| 4   | 细分    | 任意（选填） | 弯头 / 直通                              |
| 5   | 规格    | 正则     | `^[0-9]+[xX×][0-9]+$` / `^DN[0-9]+$` |

换企业规范：改 `separator`、`segments[].allowed`、`segments[].pattern`、`normalize.illegal_chars` 即可。代码零改动。

## 工程约束与设计取舍

这些是真实工程场景里暴露、并在代码里处理过的问题：

1. **选填段也要占位**：规范里"细分"是第 4 段、"规格"是第 5 段。像 `机电-桥架-镀锌钢板-200X100` 只写了 4 段的族，"规格"会错位落空被抓出来。工具强制按位置校验，不靠猜。
2. **审计前先做无损规范化**：全角横杠、下划线、乘号在中文输入法下极易产生。`机电_风管_...` 会先规范化成标准分隔符再校验，规范化后合规即判合规——避免把"只是分隔符不同"误报成违规。
3. **复检闸门**：改名后不直接算成功，而是用新名字重新校验。若建议名仍不合规，转人工，绝不"改了还错当成功"。
4. **事务整体回滚**：所有改名包在单个 Revit 事务里，任何一步失败整体回滚，不留半改状态。

## 局限与后续

- v1 只做结构化规则校验，不做中文语义纠错（如"通凤"→"通风"）
- 一次处理当前模型、单一类别
- 改名建议对"缺字段"类保守跳过，需要人工补全后再跑
- 后续：pyRevit 按钮版、LLM 语义纠错、Excel 可视化报告看板、多类别批量处理
